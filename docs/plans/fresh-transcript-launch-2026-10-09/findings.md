## Independent M2 rejection and common-boundary repair

The first delivery was rejected despite its old fixtures passing. Raw key substring search plus one canonical JSON escape is not a check of every legal JSON representation. The provider/outer JSON can encode ASCII as Unicode escapes; after decoding its content, object names, nested array leaves and even failure reason contain the key. Public isalnum classification also copied arbitrary child-controlled text. A valid contaminated receipt with extra detail passed the old counter checks, contradicting the documented unknown usage contract.

Both repositories now check decoded JSON string leaves and object pairs at the decoding boundary. The pairs hook checks duplicates before dict conversion can hide a contaminated earlier value; array scanning is iterative and does not rescan already checked objects. FF applies this check to stdout, stderr and base64-decoded provider originals. ET applies it before content extraction or v1/v2 payload return. Known contamination rejects the unchanged original; no scrubbed replacement is produced. Public reason is selected from a finite producer enum rather than character shape. A contaminated/unrecognized receipt keeps null counters, null started and incomplete usage. A separately clean receipt retains measured requests/bytes and the started fact even if stdout was rejected. Preflight zero remains distinct from unknown.

The new true FF child tests encode an alphanumeric synthetic key in JSON error_code and optionally in its receipt. ET tests traverse its actual CLI supervisor/worker private fake HTTP seam for both v1 and v2. These are offline engineering facts, not real provider authentication. No production key/config or full host environment is read into fixtures; tests set minimum synthetic child environments and use boolean safe assertions. The earlier diagnostic incident remains an unverified historical exposure and cannot be retracted.
