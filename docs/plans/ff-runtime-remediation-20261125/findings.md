# 发现

- 主收据内保留原调用、下载与费用证据。提交之后才追加次级作业日志。发布从作业存储移到业务入口，状态转换返回已落盘的结果。
- 观察投递、诊断可读和原业务结果分别核对。可恢复的终态详情不可读时留下原收据，恢复时按同一身份补投。诊断读取按候选根查找已绑定内容。
- 三表直启保留一个由本仓拥有的阶段收据，沿用已有观察状态根。输入保存 UTF-8 原始字节摘要，版本使用固定链路的源码摘要。记录区分子进程可能已启动、响应已见和已知未运行。失联只能由真实已知事实决定用量状态。

## 冷读入口

`ff_job_feedback.py get-statement-run ff-statement-run/1/<occurrence> [--observations-dir <dir>]` 通过开始观察中的 `evidence_ref` 定位。正常和已知错误返回 `done` 及原终态。活动操作返回 `pending`，强停后返回 `unknown` 及原始进展。F4 的现有 `reconcile` 调用验证原运行号、尝试、步骤后，给出其已有的 `interrupted` 或原终态及原账款含义。续查执行增量为零。

两种直启使用同一原生运行收据。按调用者可得的 `--run-id`、`--attempt-id` 运行 `get-statement-run` 或 `get-direct-run`，也可以传完整原引用。多条合法同一尝试返回可选引用，无需读原始 outbox。输入保留字节 SHA 和窄字段白名单，带有 `withheld` 明确暴露无法安全重建的字段。短财报的伴随电话会投影显式保存父步骤，并可按冻结同一身份查询。来源文件和远端内容不进入运行收据。

原始终态、详情和可重投的行在文件投递前保存。收据目录与可拒写的出箱文件分开。消费者按原行身份确认后保留可读原包。单独的 `.sent` 缺少原包及详情时不视为可读。显式 sidecar 正常成功不创建隐含确认目录。

### 自动维护和只读接口

复审发现用 `reconcile` 反向补投会产生循环依赖。两处出箱均无法写时，F4 收不到任何行，也就没有触发 lookup 的身份。改由已有 F4 `flush-observations` 动作从当前本仓收据查缺。标准状态、计划 `runs` 及 `reconcile` 只读。遗留 `reconcile --config` 等参数为兼容保留，显式业务对账仍由 `ff_job.py act --action reconcile` 在所属仓执行。

`flush-observations` 恢复三类现有记录。直启收据提供完整的原开始和终态投递内容。作业只重建本仓已记录的开始、终态或失联发现。计划收据补已知阶段及失败详情。单独的维护动作不构造新的业务请求，也不会循调用的反馈 ENV 附写上游 sidecar。每个实体用原运行、尝试和步骤写同一固定包。仍有出箱异常时保留本仓收据和非零维护状态，下轮只重试原观察。

维护及 lookup 的 `--jobs-dir` 可重复传入，使用每个实际 FF 运行根的 `.ff_jobs`。与默认原生出箱配对。自定义原生 outbox 用 `--observations-dir` 选择，明确传入后宿主过滤 ENV 也能恢复。自定义目录对应旁边的本仓直启收据目录，并只应用于列出的第一个 state root。维护的根租约只覆盖 native 写入，重复进程不启动生产者。
