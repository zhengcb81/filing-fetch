# S3/S4 filing-fetch 公开边界整改

基线为远端 `main` 的 `1adea7427675aa64640b6ff7b156d3ff5bc6973a`。总控审计日期为 2026-11-24。运行产物在本次测试自有临时目录，正式工作区的三份既有未提交 PWF 保持原样。

## 问题和实现

- 旧矩阵直接导入 CWP 配置、数据库和 reader 实现，并用 SQL 观察版本和物理原件数量。现在 CWP 批量 SourceExport v2 验证归档原件，二进制 source-reader 精确读回电话会原语言。FF 断言重复调用得到同一 SourceRef、真实发现和下载计数不增加。CWP 本仓 `tests/contract/test_source_catalog_canonical_writer.py::test_writer_deduplicates_downloaded_bytes_without_second_canonical_file` 和 `tests/contract/test_source_catalog_acquisition.py` 验证落盘与去重的内部不变量。老收据继续按它们原先的计数约定复核，本批新结果用 `w06-fresh-source-proofs/2` 标注公开证明。
- W20 已得到 SourceRef 时直接按该引用实读，遗失引用时走公开 source-query 再实读。同一绝对截止内区分已确认、明确未找到和观测失败。导入中断的证据来自合成 ET 回执中的真实供应商原件字节，使用它的 SHA，不误用转录正文 SHA，也不把未完成回执当作明确未落盘。
- ET worker 照常在真实 supervisor 下运行。HTTP fixture 由 FF 持有，支持合成成功、授权失败、限流、公开格式错误、强停和不完整结果。供应商 API、原件目录、真实密钥没有参与。财报 fixture 按公开合同返回 CN/HK/US 的请求证券身份，恢复真实 CWP 发行人校验。已有批量播种仍调用同一已安装入口公开的 command main，通过合成 provider 走真实交易。
- `FilingFetchError` 和路径识别成为可独立装载的接口。原有 import 路径仍识别同一个异常类。跨模块使用校验函数经明确公开命名。没有改变正常输出、下载限额或失败策略。快 CI 执行精确边界测试和冷启动测试，真实多仓矩阵仍显式运行。

在本仓执行，指定可用的 CWP 和 ET 代码根、两个独立的新临时根。ET 的项目测试文件可以不安装。

```powershell
python -B tools/offline_contract_matrix/run.py `
  --cwp-project <CWP源码目录> `
  --et-project <ET源码目录> `
  --owned-root <新测试数据目录> `
  --out-root <新报告目录>
```

完整报告应为 41 个 PASS，oracle 无发现，`restore.restored=true`。单个用例超过 30 秒或整体达到 180 秒应如实保留 PARTIAL。先单独诊断慢例和宿主争用；选择性报告不构成全量验收。


前两轮证据未覆盖全 41 例。本页末尾记录最新正式复验。S3 后续生产拆分还包括 identity client 的传输分离、job feedback 与 runner 的反向调用、顶层 CLI 渐进拆分。后续变更沿各自原始请求和复用行为测试进行。

## Windows 最终来源证明和 W20 进程恢复

W07 两次同为 278 次已观测子进程启动，完整用例用时分别为 90.29 秒（41 PASS）和 175.20 秒（40 PASS、1 PARTIAL）。最近的六例双 worker 中，三项场景在 30 秒处结束，最终来源证明耗时 10.98 秒。随后三个场景逐项独立重跑的业务阶段在 18.79 至 23.12 秒之间。旧启动记录把部分 `python -m` 路由归入 other_python，无法精确分解所有进程耗时。

现在复用已等待全部写入结束的 worker 池并行做各组的来源实读。并行上限和批次截止保持原样，每组只读自己的测试 wiki 并使用自己的证据文件。合并仍按组编号，先结束的组不能覆盖先编号组的证据。一组缺失证据时报告保留其他组的已完成事实，退出结果保持失败。

同一对 CN/HK 年报下载复用的真实合成端到端对比，两次均观察到 2 PASS、两组最终来源证明、零 oracle 发现和完整清理。最终证明的测量为串行 3.5473 秒、并行 1.6211 秒。总耗时为 25.4402、16.1617 秒，包含其他阶段及机器负载变化。报告 SHA-256 分别为 `2b9f05b5664ced74ad0328afb2b1ecac32481b003a0ab7196036df3961cef299` 与 `465bfa92ed9f372e3724abb646629b7d8b25be63eeceaf53d01d7e15cbcf3f6b`。这次定点对比没有重新验收全部 41 例。

总控的 W20 单例报告 `8b07d67c…182f3` 展示了已导入且有完整供应商回执的首次运行、超时的第二次和启动后没有进运行记录的第三次。旧代码在创建进程和分配 Windows Job 后才计算剩余时间，超时异常可以越过回收代码。现先取得截止窗口，Windows 冻结启动子进程直到 Job 分配并再次确认剩余时间，异常回收后保留 stdout、stderr 和结构化阶段。每一次真实启动都记录包含回收的耗时，超时不续预算，也不会把准备过的请求当成启动过。

使用同一批次中的 CWP `bbcee7ba26080a3261459e8377dcd09524fb2ea3`、ET `2fc8f92eaf1f8a5406ec63fbf384fc51ab72b4f9` 精确代码，单 worker 重跑 W20 丢失答复一例，业务阶段 25.9314 秒（原 30 秒窗），总耗时 41.5893 秒，oracle 零项，临时数据恢复。三次 FF 进程分别 11.6831、5.9694、6.7578 秒，合成 GET 为 1、0、0，公开原件再次确认；最终证明 3.2363 秒。真实网络、翻译均为零。报告 SHA-256 为 `ec854e069bbb77488b071c887a251a7286f96de42fb9ee73f6eb94a4dd992402`。这次证明确认回放进程阶段占了本例大部分预算，最终证明优化不能替代逐次进程诊断。

来源并行阶段所用回归组 86 项通过，进程生命周期及合同组 63 项通过。追加的截止已过、Job 分配失败、分配后禁止释放、回调异常四例复验通过。Ruff 和公开入口 mypy 通过。本页末尾有完整矩阵复验。

独审故障注入另发现，原终止异常可能被 Job.close 异常取代，或在终止失败后跳过进程回收。W20 和正式 FF transport 现在共用进程所有者的回收顺序。终止失败时先尝试 Windows Job 的兜底关闭，再以原清理窗口等待回收，不续期。有原始失败时保留它，并另外记录后续清理的阶段与类型。W20 留下这一结构化回执，正式 transport 在原异常附上脱敏的阶段和类型。

最终故障回归涵盖原始超时、已完成非零退出及 stderr、进程收尾错误和 F4 冷读。真实的已完成退出码、stdout 与 stderr 保留为首要 ChildFailed；成功退出但收尾出错按既有清理失败语义处理。冷进程通过已有 `get-diagnostic` 可读到 `process_cleanup` 的阶段和类型。额外 Python note 不进入收据。最终合并回归 149 项通过，精确功能指纹 `51998da5588f670930010381cc72c3e4b84ba93e48d51ad088d85d5e89356220`。

独立复核以同一指纹重跑 13 个关键测试，全部通过。


## WSL 全矩阵复验和夹具隔离

固定 FF `830909f8f44e8643de3da129878d0a542efce135`、CWP `bbcee7ba26080a3261459e8377dcd09524fb2ea3`、ET `2fc8f92eaf1f8a5406ec63fbf384fc51ab72b4f9`，三个实际 Git 根与代码绑定均通过。Ubuntu 24.04.4 LTS、Python 3.12.3，保持两 worker、单例 30 秒、批次 180 秒。六例先导 6/6、10.9069 秒，SHA-256 `06e6fdd75293d18b98151d89e9a2e1ac92ab1b97f8d2043951fe8140fdd38988`。正式 41 例在 38.503 秒内均实际运行，35 PASS、4 FAIL、2 PARTIAL，oracle 六项。最慢一例 4.127 秒。23 个分组原文证明通过，真实供应商、费用、翻译均零，生产文件元数据与测试目录恢复。报告 SHA-256 `fba9f717b4937faf195e53b76c563091cc04c8955589a8a9d9e4f6e7ae6ddb2f`，完整尝试归档 SHA-256 `4c97f860054b679275989d98d14637b7916ceebd4d142f99e9f8cf63bbbac151`。

六例皆在供应商调用前经过 CWP 本地准备并收到 `local_metadata_incomplete`、`local_candidate_scope_unresolved`，真实本地夹具 GET 为零且未触达预算。g2 的美股年报、半年报、IPO 和增发四例各实读一个 50 字节对象，该组唯一匹配对象为用于 `local_txt_exact_reuse` 的旧 TXT 夹具。IPO 的同一请求在没有该夹具的先导测试中 GET 两次并入库。g1 的 `incomplete_sidecar_metadata_gap` 先写入 613 字节的 A 股年度原文，后续 `original_wrong_sha`、`original_max_bytes` 均在走供应商前实读一个 613 字节对象。另组 `original_wrong_mime` 实际发起两个夹具请求并由 CWP 校验拒绝。

FF 本仓先修复夹具作用域。上述两个专门验证本地遗留状态的用例使用各自的短路径测试资料库、代理状态与种子。同一 worker 串行完成组内原作业，种子计入单例原截止，原件实读、计数、证据、清理覆盖每个实际资料库。保持原 41 个用例的请求和验收条件，以及 SHA、MIME、字节上限和匹配原文元数据缺口的拒绝路径。

CWP 所属的后续问题单独保留。混合文种生产目录中的一个未证明 scope 的原件会在 `_discover_source_groups` 阻止其他种类或期次的正常获取。需要在 CWP 本仓复现，区分可以用所有者凭据证明不相关的对象与可能就是请求目标的对象。匹配原文的真实性和防重复承诺继续保留。隔离矩阵夹具不会解决这项产品行为。

TDD 在旧版观察两种顺序均混入旧 TXT；另用控制时钟复现种子越过单例期限后仍进入用例。候选修复后三种执行形态与到期路径通过，相关 W06、W07、DU8、DU10 回归共 273 项通过，Ruff 和 diff 检查通过。总控在精确功能指纹 `697fcd9cc432e329e274435be531cb9e8a86dbf9e547ce27a41e9b1339a1d641` 上独立运行 7 项通过并接受边界设计。正式 41 例复验以独立候选提交为准。
